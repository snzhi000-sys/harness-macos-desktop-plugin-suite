dsh-docker — promo narration (~55 seconds, 7 slides)
=====================================================
Read this aloud while screen-recording. Each block starts on its slide; hold
each slide ~7-8 seconds. Advance with the space bar or right arrow.

[Slide 1 — hero]
Meet dsh-docker: typed, guarded container control for DeepSeek Harness.
Structured Docker access your agent can't destroy by accident.

[Slide 2 — the headline]
Real objects, never scraped prose. Fourteen structured tools — ps, logs,
inspect, exec, lifecycle, compose — every call returns canonical JSON,
guarded by an approval gate, scoped to your project, rendered as
replayable status tables.

[Slide 3 — the problem]
Today agents guess. No container plugin exists, so a debugging agent
shells out to raw docker ps, scrapes prose — and can just as easily fire
compose down -v and wipe a volume.

[Slide 4 — guardrails that matter]
So destructive ops ask first: rmi in-use, rm running, prune --all, and
down -v route through a human approval gate — fails closed, one-shot
grants. A monotonic guard backstops it — even a preempting allow can't
bypass the approval token.

[Slide 5 — project-aware]
Project-aware targeting: stop dev-api means your local compose service,
not a coincidentally-named container. A pure resolver walks up for the
compose file and scopes every call with -p and -f. Ambiguous refs return
candidates, never a guess.

[Slide 6 — health and renderer]
The agent checks the right container first: an opt-in health line per
service each step — api up, db up, worker exited — plus honest,
truncation-flagged logs in a collapsed status table.

[Slide 7 — install]
Install in one command: dsh plugin, profile web, add,
github-Jesse-njx-dsh-docker. Real objects. Real approvals. Real stacks.
