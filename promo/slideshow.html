the headline

Real objects, never scraped prose.

typed

14 structured tools

ps · logs · inspect · exec · start/stop/restart · rm/rmi/prune · compose up/down/ps. Every call returns canonical JSON — Code Mode gets real rows.

guarded

Approval gate

Destructive ops pause for a human. No channel, no approval? Refused — fails closed, one-shot grants only.

project-aware

Your stack, not a namesake

`stop dev-api` targets the local compose service via `-p`/`-f` and project labels — never a coincidental container.

replayable UI

Status tables in the web app

Collapsed-by-default tables for ps/compose_ps/logs — with an honest `truncated` flag on capped log pulls.

the problem

Today, agents guess.

No container-control plugin exists in the ecosystem. An agent debugging a failing integration test shells out to raw `docker ps`, scrapes prose… and can just as easily fire `docker compose down -v` and wipe a volume.

before

Raw shell, scraped text

Prose parsed by luck. The model re-reads human formatting to find ids and states.

the danger

One command away from data loss

`rm -f`, `prune -a`, `down -v` — each runs with zero sign-off.

guardrails that matter

Destructive? Ask first.

docker_rmi "app-api:latest" — image in use by container app-api-1
routing

tools/pre-execute policy

A pure `classify()` judges each call's effect. Guarded ops route through `ctx.approval` — approval absent fails closed to unavailable.

backstop

ctx.tools.guard()

A monotonic deny no later listener can undo. Even a preempting "allow" can't bypass the approval token check.

Read-only exec is free. `execReadOnly: false` flips that for operators who accept the risk.

project-aware targeting

`stop dev-api` means your service.

$ docker_stop { container: "dev-api" }
docker compose -f ./docker-compose.yml -p dev stack -f … stop dev-api

A pure ProjectResolver walks up for the compose file, derives the project name, and scopes every call with `-p` / `-f` and compose project labels. Ambiguous refs return candidates — never a guess.

opt-in intelligence

The agent checks the right container first.

[dsh-docker] dev services: dev-api ▲up   dev-db ▲up   worker ▼exited(1)

Each pre-step injects one compact health line per compose service — durable context the next request sees, capped at 12 services, skipped when no stack is detected.

web client

Status tables, replayable

One stable node per tool call, keyed by callId — collapsed by default, expandable on click.

honest logs

Truncation surfaced

A capped `docker_logs` pull never reads as complete — the flag rides the durable meta.
