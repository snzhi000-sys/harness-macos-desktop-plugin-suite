# Agent Note：启用可恢复的工作区可写 Shell 审核

状态：已实现

[English](2026-09-05-recoverable-workspace-shell-review.md) | 中文

## 问题

第三轮 Shell 快照生命周期可以识别变更，但尚未把被删除内容转交给 File Edit 持久账本。此时启用会让前台 `rm -rf` 删除数据后只留下内部事务，无法获得正常的批次审核、重启恢复和面向用户的拒绝还原能力。

## 决策

File Edit 现在会在返回结果前结算每个发生变化的 `workspace-write` 前台 Shell 事务。工作区事务租约会一直持有到持久账本结算完成，因此其他 Session 或子代理不能在磁盘对账与账本提交之间，对相同或互相包含的根目录启动新事务。新增和修改的普通文件进入现有会话基线账本。被删除文件和顶层删除目录从已验证的命令前快照复制到会话 quarantine，并使用与 `file_delete` 相同的 `deletionBatchId` 元数据。目录载荷保留嵌套结构、空目录、文件模式、二进制内容和未跟随的符号链接。临时 Shell 事务只有在 SHA-256 内容验证完成后才能释放。

v7 状态格式通过 fsync 临时文件和原子改名写入紧凑审核账本，并继续在 File Edit 内读取旧账本。没有普通文件的目录使用一条私有锚点记录，使其隔离批次仍能显示、接受或恢复。部分文件处理会保留批次，最后一条记录结算后再清理隔离区。整批拒绝先验证并恢复完整载荷，再清除墓碑。

快照管理器可以恢复 Host 崩溃后遗留在 `running` 或 `captured` 的事务。File Edit 在新的可写 Shell 开始前和读取审核快照时执行恢复。进程树残留造成的失败事务继续保留为证据，并在账本提交后写入标记，避免重启重复生成批次。

产品组成启用 `shellTransactionLifecycle`。因此，Shell 门禁会在解析策略为 `workspace-write` 且具有一个绝对工作区根目录时，允许受管的前台 `bash`、`shell` 和 `pwsh`。只读行为不变。一次性提权到 `workspace-write` 仍由审批服务负责，只有审批通过后才会在同一快照事务内执行。后台任务、持久终端、未受托管的兼容 Shell 和 `danger-full-access` 仍被拒绝，因为它们的可写生命周期或根目录集合不受本事务覆盖。

## 考虑过的替代方案

**命令结束后再把删除路径移入隔离区。** 不采用，因为破坏性命令结束后原路径已经不存在，只有命令前快照可以作为恢复依据。

**永久保留 Shell 快照，并让界面实现第二套审核模型。** 不采用，因为这会重复删除语义，使结构化工具与 Shell 行为不一致。快照载荷改为转入现有 quarantine 格式。

**启用无边界的全部权限 Shell。** 不采用，因为工作区快照无法声称覆盖根目录外的写入。权限模式提示与更广策略选择留在后续阶段处理。

## 结果

该产品配置允许可写前台 Shell，同时保持严格且可跨重启恢复的文件审核。命令可能在进程层完成后因无法证明结算完整而返回审核失败；此时快照会保留，系统不会声称成功。快照成本随完整可写根目录增长，并受 51,000 条目、8 GiB 逻辑内容和 64 层深度限制。同根目录代理以并发能力换取确定的账本边界，不相交工作区仍可并行。
