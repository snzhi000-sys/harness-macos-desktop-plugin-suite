# Agent Note: 建立 Shell 修改前快照事务基础

Status: implemented

[英文](2026-09-05-shell-prechange-snapshot-foundation.md) | 中文

## Problem

File Edit 无法依靠执行后文件系统观测来安全重新开放可写原始 Shell。破坏性系统调用可在 watcher 报告路径前删除数据，而且事后枚举目录元数据并不等于可恢复的修改前映像。因此产品需要一个可独立测试的事务：它要么在命令派发前为每个已声明可写根建立完整且经验证的快照，要么在不启动命令的情况下失败。

## Decision

`plugins/file-edit/host/shell-snapshot-transaction.mjs` 负责第 2 轮快照基础设施。事务在 `dsh-file-edit-state/shell-transactions` 下使用不透明 ID 和 Session ID 哈希，通过 `preparing`、`ready`、`running`、`captured`、`failed` 和 `discarded` 状态写入带版本 manifest，并将负载与 manifest 元数据分离保存。

管理器要求显式、绝对且不互相包含的可写根。它完整、确定性地枚举普通文件、目录和符号链接，但不跟随链接。特殊文件、硬链接文件、不可读条目、超出深度、超出条目数和超出逻辑字节上限都会被拒绝。macOS 由于 Node 在该平台对 `COPYFILE_FICLONE_FORCE` 返回 `ENOSYS`，因此对每个完整根目录只启动一个不经 Shell 的直接 argv 调用 `/bin/cp -cR`；注入适配器和非 macOS 平台保留逐文件克隆契约。只有明确的不支持或跨卷错误才允许降级到物理复制，而且必须在复制任何文件前按整棵树逻辑大小确认可用空间与保留量。每个负载文件仍按大小和 SHA-256 校验。

快照准备失败会移除整个隐藏暂存目录。紧凑的 version-2 manifest 在既有内容哈希外记录 ctime 元数据。准备期校验和命令后的稳定性采样，只有在类型、大小、模式、mtime、ctime、所有者与组全部一致时才复用哈希；变化和新增文件仍必须在分类前完成哈希。就绪事务会在进入 `running` 前原子改名到正式位置。结算时不依赖 watcher，而是将当前完整根目录与 manifest 对比并区分新增、修改和删除条目。命令结束后会对根目录取两次样本；如果目录仍在变化，事务会以 `snapshot-finalize-stale` 失败并保留。只改变时间戳不会形成修改，内容、类型、模式、所有者和符号链接目标变化仍会保留。watcher 路径只作为诊断候选写入，不能决定 change set。

File Edit Host 在私有组成配置 `shellTransactionLifecycle` 为 `true` 时让 Shell 家族的 `tools/execute` 经过该生命周期，产品 Profile 已对有界的 `workspace-write` 前台 Shell 启用它。管理器会串行化规范根目录相同或互相包含的事务，包括不同 Session 和父子代理的调用，并持续持有所有权直到账本提交完成；互不相交的根目录可以并发。该路径会让成功、非零退出、抛错、超时和取消统一经过同一个 finalizer。前台 Shell 执行器还会在直接进程关闭后等待受管进程树；残留辅助进程会被终止并报告为 `SHELL_PROCESS_TREE_SURVIVED`，File Edit 即使没有观察到文件变化也会保留失败事务。

过期暂存与 ready 事务只会在可写事务或显式审核恢复调用管理器时回收，不进入桌面端首屏启动路径。隐藏的 `preparing` 与未使用的 `ready` 状态保留一小时。已经标记为提交到持久账本的事务保留七天用于诊断，之后删除。未提交的 `running`、`captured` 和 `failed` 证据没有按时间删除规则。

## Alternatives considered

**把 APFS 克隆成功当作足够的验证。** 未采用，因为在多文件快照组装过程中源文件可能变化，而克隆可用并不能建立目录级的一致时点。

**跟随符号链接并保留硬链接拓扑。** 未采用，因为链接可逃离已声明根目录，而硬链接恢复具有当前账本无法安全表达的别名语义。符号链接按链接记录，硬链接 fail closed。

**每个文件启动一个克隆进程。** 未采用，因为大目录的主要成本会变成进程启动。根目录级递归 COW 把进程数限制为每个声明根目录一个，同时由独立构建的清单和完整负载哈希校验维持安全边界。

**change set 可用后立即在产品中启用生命周期。** 未采用，因为删除批次、崩溃恢复和账本所有权仍未完成。仅有已捕获的 change set 还不足以声称 Shell 审核可恢复。

## Consequences

工程具备有界且确定的修改前快照，以及为所有命令结束方式生成可重放变更元数据的统一内部生命周期。失败用例可以证明命令回调从未调用，命令结束后仍变化的根目录不会被静默结算，前台辅助进程也不能在成功结果后不受关注地继续存活。

产品可以审核有界的可写前台 Shell，同时保留完整枚举和负载校验。默认 51,000 条目和 8 GiB 逻辑大小限制约束峰值工作量，并允许分片目录下的 50,000 文件基准。同一目录树内的第二个代理会等待，不相关工作区仍可并发。失败事务进入账本后，诊断证据最多占用七天状态空间；未提交证据有意要求显式恢复，而不会因过期时间被删除。
