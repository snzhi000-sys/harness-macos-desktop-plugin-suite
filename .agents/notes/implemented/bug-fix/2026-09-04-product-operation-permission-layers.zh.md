# Agent Note: 分层管理产品操作权限而非禁用可写工作

Status: implemented

本决策中的原始 Shell 部分已被[在具备删除前快照前禁止不可恢复的可写 Shell](2026-09-05-block-unrecoverable-shell-until-snapshots.md) 取代；受控 `lark_cli` 的权限决策仍然有效。

[英文](2026-09-04-product-operation-permission-layers.md) | 中文

## Problem

产品的文件审核插件会在执行前拒绝所有原始 Shell 工具，原因是任意命令可以写入或删除文件，却无法提供结构化文件工具那样的精确修改前快照和隔离恢复保证。独立的受控 `lark_cli` 工具恢复了飞书能力，但第一版会在每次远程写入前申请审批。审批策略为 `never` 的会话会确定性拒绝所有请求，所以普通文档更新和上传仍无法运行。这种组合通过移除常规 Agent 生产力来维持更强的审核声明：构建脚本、生成器、包管理器和普通远程文档写入都不可用。

## Decision

前台 `bash`、`shell` 和 `pwsh` 调用通过 Harness 正常的会话沙箱执行。`dsh-file-edit` 在有界的调用期间使用工作区监听器和执行前后元数据对账，再把检测到的工作区变更加入归属会话的审核账本。显式命名的外部文件目标继续使用现有的窄口径捕获。后台 Shell、持久终端和未受托管的兼容 Shell 入口没有一个可关闭审核事务的结束点，因此仍由执行前策略和最终单调 guard 双重拒绝。

需要精确修改前快照或可恢复删除时，仍优先使用结构化 `write`、`edit`、`file_move` 和 `file_delete`。Shell 审核层提供执行后可见性，会话沙箱才是写入边界。特别是 `danger-full-access` 可以修改工作区观测无法发现的未命名外部路径。

受控 `lark_cli` 工具在不额外申请审批的情况下执行普通文档创建、更新、导入、上传和其他非破坏性写入。删除、回滚、退出登录或移除访问权限的命令仍需要 `allowed-once`；因此审批策略 `never` 继续使这些高风险操作 fail closed。该工具保留 argv 允许列表、可信执行文件、完整沙箱执行要求、工作区输入路径包含性、狭窄的可写状态根和凭据脱敏。

## Alternatives considered

**保留无条件原始 Shell 拒绝，为每个外部程序增加一个结构化工具。** 未采用，因为它只能逐个修复已知命令，包脚本、生成器和未来需要认证的 CLI 仍不可用。高价值集成仍优先结构化工具，但它不能取代 IDE Agent 预期的通用前台执行能力。

**允许所有 Shell 和终端生命周期。** 未采用，因为后台即时确认或持久终端发送无法标识文件系统影响何时结束。在确认时关闭审核会错误声称捕获了之后的写入。

**每次普通飞书写入前都请求审批。** 未采用，因为 `never` 意味着需要审批的操作无法运行，即使受控工具已有独立文件系统和命令边界，创建或更新也会不可用。删除和移除访问权限等一次性人工决定能实质降低风险的操作仍保留审批。

**解析命令文本，只允许表面安全的 Shell 操作。** 未采用，因为展开、脚本、解释器、子进程和符号链接使命令字符串分类既不完整也无法强制。操作系统沙箱控制写入范围，观测机制提供审核可见性。

## Consequences

前台构建和自动化命令可以按选定的会话沙箱运行，检测到的工作区变更会出现在 File Edit 审核中。动态新建文件不再只依赖单次文件系统监听交付，因为有界元数据对账提供后备。对于过深、已忽略或特别宽广的目录树，有界对账集之外仍依赖监听器交付，因此该机制不声称事务完整性。

普通飞书文档写入现在可以在 `never` 会话中工作，而破坏性和移除访问权限命令仍不可用。需要可恢复删除的用户使用 `file_delete`；选择 `danger-full-access` 的用户接受未命名外部 Shell 影响不在 File Edit 完整发现范围内。
