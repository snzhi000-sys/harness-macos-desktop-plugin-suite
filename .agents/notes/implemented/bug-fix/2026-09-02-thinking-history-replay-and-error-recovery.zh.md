# Agent Note: 思考历史回放与失败恢复状态

Status: implemented

[English](2026-09-02-thinking-history-replay-and-error-recovery.md) | 中文

## Problem

DeepSeek 思考请求可能先接受一条 assistant 响应，却在后续工具步骤中拒绝请求，因为更早的 assistant 历史缺少 `reasoning_content`。此外，结构合法的 pi-ai 回放记录可能含有 Harness 最终消息中不存在的终止态不完整块，导致该会话后续每次请求都在到达提供方前失败。持久轮次失败也会在后续回答成功后继续表现为当前错误。

## Decision

DeepSeek 适配器在序列化历史前解析思考模式。思考模式开启时，每条 assistant 消息都携带 `reasoning_content`：已记录的推理原样回传，没有推理的 assistant 消息携带空字符串。关闭思考模式的请求省略该字段。

pi-ai 适配器继续严格校验回放格式及来源提供方／模型身份。如果最终 Harness 块是原生终止响应的有序子集，回放会保留匹配的私有元数据并忽略未完成的多余块。如果二者无法对齐，适配器会把持久消息转换为外部的、与提供方无关的历史，而不是拒绝之后的每次请求。

终态轮次失败继续作为持久历史事实保留。后续出现已定稿文本回答时，更早的失败行会转为已恢复状态；新的 Agent 运行会清除上一次无轮次定位的实时错误。重复且相同的实时通知不会再次发布未变化的状态。

## Alternatives considered

**只为包含工具调用的 assistant 消息回传推理。** 不采用，因为 DeepSeek 会校验思考模式请求中的每条 assistant 历史，包括更早步骤或轮次中的普通回答。

**拒绝所有回放与内容不匹配的情况。** 不采用，因为原生终止响应可能包含从未成为持久 Harness 内容的不完整块；在这里严格失败会让一次不完整响应永久锁死会话。

**后续成功后删除或隐藏历史失败。** 不采用，因为 `turn/end(error)` 是权威会话事实。已恢复展示会保留该事实，同时把它与当前运行结果区分开。

## Verification

序列化测试覆盖思考模式开启与关闭、包含与不包含推理的 assistant 消息、工具调用和纯推理响应。pi-ai 转换测试覆盖有序子集元数据恢复、安全外部回退、格式错误元数据和提供方／模型身份检查。Client 测试覆盖失败恢复展示，以及新运行对实时错误的失效处理。产品 App 验证会在发布固定 Dev 输出前检查包内 Runtime 和 Client bundle 是否包含这些行为。

## Consequences

思考模式后续请求会按提供方要求重复传入既有推理，因此输入量增加。带有陈旧但结构合法的 pi-ai 回放元数据的会话仍可继续使用，代价是在无法对齐时放弃提供方私有复用元数据。历史失败继续可见，但恢复后不再表现为最近一次运行结果。
